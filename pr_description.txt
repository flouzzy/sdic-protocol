## Summary of Changes
This PR standardizes the "Action Ledger" data structure to facilitate multi-agent synchronization and Swarm Consensus. It implements a strict JSON schema for intent proposals, forcing deterministic inter-agent communication instead of probabilistic direct interaction.

## Rationale & Architectural Impact
Unstructured agent-to-agent communication risks state drift, race conditions, and prompt injection propagation. By standardizing an append-only Action Ledger with strict schema validation (`"additionalProperties": false`) and cryptographic canonical verification, this upgrade mathematically confines multi-agent orchestration. It protects enterprise systems by ensuring agents only communicate via deterministic, host-verified intents.

## Proposed Specification Changes
- **Target Component:** Pilier IV: The Action Ledger
- **Modification:** Added a strict JSON schema (`MultiAgentActionLedgerEntry`) enforcing `"additionalProperties": false` and a unified structure (including `correlation_id` and canonical cryptographic signatures) to act as the single source of truth for Swarm Consensus.

## Backward Compatibility
This change is fully backward-compatible with v1.0.0-draft implementations. Single-agent setups can safely ignore multi-agent fields (`correlation_id`, swarm proposed actions), while multi-agent setups simply enforce this schema on existing Action Ledger mechanics.
