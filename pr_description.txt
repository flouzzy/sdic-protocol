## Summary of Changes
This PR introduces SDIC-ERC-0088, which proposes an enhancement to neutralize prompt injection attacks at the runtime level via Deterministic Execution Mapping. By obfuscating sensitive parameters into single-use cryptographic tokens (UUIDs) before context ingestion, the autonomous agent is forced to return these tokens instead of arbitrary strings.

## Rationale & Architectural Impact
Prompt injection payloads often attempt to trick the AI into emitting unauthorized commands or altering sensitive string parameters. While Semantic Determinism (Pilier II) ensures the output format is valid, it traditionally cannot distinguish between a legitimate and a maliciously forged string. By enforcing a deterministic token map, this upgrade eliminates the AI's ability to synthesize arbitrary string commands, reducing the attack surface for parameterized intents to zero.

## Proposed Specification Changes
- **Target Component:** Pilier II: Semantic Determinism
- **Modification:** Added a requirement for "Deterministic Execution Mapping" where the host application maps sensitive parameters to unique UUIDs, and introduced a standardized `MappedExecutionIntent` JSON schema that enforces `"additionalProperties": false` and strictly requires UUID formatting for these parameterized fields.

## Backward Compatibility
This is a breaking change for systems that currently rely on the LLM to output raw string parameters for execution. Host applications must be updated to implement the token generation and reversal mapping algorithm, and the corresponding JSON schemas must be updated to expect UUID formats instead of strings.
