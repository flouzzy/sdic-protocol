## Summary of Changes
This PR introduces SDIC-ERC-0008, an architectural extension establishing a standard for Deterministic Canary Verification. It allows the deterministic host application to inject a cryptographically secure, single-use token into the cognitive context to detect and filter Prompt Injection attacks at runtime.

## Rationale & Architectural Impact
To protect enterprise systems from AI unpredictability and malicious prompt injections, we need a runtime filtering mechanism that does not rely on probabilistic heuristics or secondary LLM evaluations. By forcing the model to reproduce a meaningless cryptographic string from the system prompt in its final output, we create a fragile instruction bond. If an attacker's payload successfully overrides the model's instructions, the model will inevitably drop or corrupt the Canary Token, instantly translating a probabilistic cognitive failure into a deterministic schema validation failure.

## Proposed Specification Changes
- **Target Component:** Deterministic Control Layer / Semantic Determinism
- **Modification:** Added a requirement for the host application to generate a single-use Canary Token ($Canary_t$) injected into the system prompt. All JSON schemas processed by the Deterministic Control Layer must be extended to enforce a `security_canary` field using `additionalProperties: false`, which is then deterministically verified against the expected token at runtime.

## Backward Compatibility
This change requires an update to the system prompts and JSON schemas of all deployed autonomous agents. Implementations of v1.0.0-draft without Canary Token support will not be able to validate intents enforcing this new schema, requiring host applications to adopt the token generation mechanism and inject it into the prompt pipeline.
