## Abstract

This standard proposes an architectural optimization to the SDIC-1 protocol to drastically reduce the latency overhead of the Guardrails layer. By pre-compiling the strict JSON Schema into a deterministic Finite State Machine (FSM), the Guardrails layer can validate the semantic intent stream token-by-token. This ensures that non-compliant generations are aborted instantly, reducing compute waste and completely eliminating the latency overhead associated with post-generation schema validation.

## Motivation

Within the SDIC-1 architecture, the Semantic Determinism layer enforces that all AI-generated intents strictly adhere to a pre-defined JSON Schema. Traditionally, this requires the Large Language Model (LLM) to complete its entire generation sequence, after which the host application parses the full JSON payload and validates it. In enterprise environments demanding high-frequency agentic orchestration, this wait-and-validate pattern introduces unacceptable latency overheads and wastes computational resources on generating ultimately invalid tokens. A mechanism is needed to enforce schema adherence with zero additional latency while maintaining absolute deterministic isolation.

## The High-Speed Train Switcher Analogy

Imagine a high-speed train network where a dispatcher sends trains towards various destinations. Instead of letting a train complete its entire journey to check if it arrived at the correct destination safely and returning it if it didn't, the network uses automated track switchers at every junction. The switchers know the exact valid routes in advance. As the train moves, each switcher instantly verifies the next segment. If the train attempts to take an invalid track, the switcher immediately stops the train safely before it can cause a collision, rather than waiting for the journey to finish.

In this architecture:

- **The high-speed train** represents the streaming tokens of the JSON intent generated by the AI model.
- **The complete journey** represents the full generation of the semantic intent payload.
- **The automated track switchers** represent the deterministic Finite State Machine (FSM) derived from the JSON Schema at the Guardrails layer.
- **The safe derailment at invalid tracks** represents the instant token rejection and connection termination by the Guardrails layer, preventing the latency overhead of full generation and subsequent post-validation.

## Specification

### 1. Finite State Machine Compilation

Before execution, the Guardrails layer MUST compile the expected JSON Schema into a deterministic Finite State Machine (FSM). The FSM represents all valid sequences of characters (or tokens) that satisfy the strict schema, including `"additionalProperties": false` constraints.

### 2. Token-by-Token Stream Validation

During the AI's generation phase, the output MUST be streamed to the Guardrails layer. For each emitted token $T_i$, the Guardrails layer updates the FSM state.

Let $S$ be the state of the FSM.
$S_{t+1} = \delta(S_t, T_i)$

If $\delta(S_t, T_i)$ transitions to an invalid state (i.e., the token violates the schema), the Guardrails layer MUST instantly terminate the generation stream and raise a validation exception, effectively aborting the probabilistic model's execution early.

### 3. FSM Configuration Schema

To standardize the instantiation of the FSM validator, the configuration MUST adhere to the following strict JSON Schema:

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "FSMGuardrailConfig",
  "type": "object",
  "properties": {
    "schema_id": {
      "type": "string",
      "format": "uuid"
    },
    "strict_mode": {
      "type": "boolean",
      "description": "Enforces compilation with additionalProperties: false universally."
    },
    "max_token_buffer": {
      "type": "integer",
      "minimum": 1
    },
    "abort_on_violation": {
      "type": "boolean"
    }
  },
  "required": [
    "schema_id",
    "strict_mode",
    "max_token_buffer",
    "abort_on_violation"
  ],
  "additionalProperties": false
}
```

### 4. Sequence Diagram

```text
+----------+                     +------------------+                  +------------------+
| AI Model |                     | Guardrails Layer |                  | Host Application |
+----------+                     +------------------+                  +------------------+
     |                                     |                                     |
     | 1. Stream Token T_1                 |                                     |
     |------------------------------------>|                                     |
     |                                     | 2. FSM State Transition             |
     | 3. Stream Token T_2                 |                                     |
     |------------------------------------>|                                     |
     |                                     | 4. FSM Invalid State Reached        |

     |                                     | 6. Validation Exception             |
     |                                     |------------------------------------>|
```

## Backward Compatibility

This optimization is fully backward compatible with the v1.0.0-draft of SDIC-1. It does not alter the final output format but optimizes the validation pipeline. Systems incapable of stream validation may seamlessly fall back to post-generation full-payload schema validation without any structural modifications.
