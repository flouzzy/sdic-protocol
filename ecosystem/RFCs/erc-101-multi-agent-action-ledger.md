## Abstract

This standard proposes a deterministic JSON Schema for the SDIC-1 Action Ledger, specifically tailored for multi-agent synchronization and Swarm Consensus. It defines a cryptographically secure, language-agnostic data structure to ensure that autonomous agents can propose state mutations and achieve consensus securely without circumventing the deterministic control layer.

## Motivation

As AI-native architectures increasingly rely on multi-agent systems ("Swarm Consensus"), a critical vulnerability arises: non-deterministic routing, synchronization conflicts, and compromised state integrity when multiple probabilistic agents interact simultaneously. Currently, the SDIC-1 standard specifies a general Action Ledger for a single agent but lacks a standardized schema to handle asynchronous intent proposals and consensus protocols among multiple distinct agents. This ERC introduces a standard Action Ledger schema designed to secure Swarm Consensus, ensuring state transitions are safe, auditable, and mathematically deterministic.

## Specification

The Multi-Agent Action Ledger strictly requires intents to be validated against a deterministic JSON Schema before any consensus mechanism evaluates them. The system operates entirely outside of the AI Sandbox.

### Analogy: The Orchestrated Symphony

Imagine a grand symphony orchestra. The musicians are incredibly talented but fundamentally creative and improvisational (the probabilistic agents). If everyone played what they felt like at the same time, the result would be chaotic noise (non-deterministic state degradation).

The conductor acts as the central coordinator, but the true foundation of harmony is the sheet music. The sheet music represents the precise, agreed-upon rules of engagement. Each musician reads their specific part and submits their performance intent (the notes they are about to play) according to the timing and structure dictated by the sheet music. Only when all sections submit their notes in accordance with the harmonic structure does the symphony resonate beautifully and powerfully.

In this technical architecture:

* **The Musicians:** The multiple probabilistic autonomous agents operating in parallel.
* **The Submitted Notes:** The raw semantic `Intent_Proposal` generated by each agent.
* **The Sheet Music:** The strict JSON Schema validator that ensures each proposed intent matches exactly what is expected.
* **The Symphony Resonating:** The Swarm Consensus mechanism, which only evaluates intents that perfectly adhered to the sheet music (JSON Schema) before committing a state transition in the deterministic execution engine.

### Strict Data Schema

All intents proposed for Swarm Consensus MUST adhere strictly to the following JSON Schema. To prevent unspecified key injections, `"additionalProperties": false` is strictly enforced.

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "SwarmConsensusIntent",
  "type": "object",
  "properties": {
    "agent_id": {
      "type": "string",
      "pattern": "^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}$",
      "description": "The UUIDv4 of the proposing agent."
    },
    "swarm_session_id": {
      "type": "string",
      "pattern": "^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}$",
      "description": "The shared session UUID for the current consensus cycle."
    },
    "proposed_action": {
      "type": "string",
      "enum": ["commit_state", "request_clarification", "veto_proposal", "merge_data"]
    },
    "payload": {
      "type": "object",
      "description": "The deterministic data payload for the proposed action.",
      "additionalProperties": false,
      "properties": {
        "target_entity": { "type": "string" },
        "mutation_diff": { "type": "string" }
      },
      "required": ["target_entity"]
    },
    "cryptographic_signature": {
      "type": "string",
      "pattern": "^[a-fA-F0-9]{128}$",
      "description": "The cryptographic signature of the canonical intent."
    }
  },
  "required": [
    "agent_id",
    "swarm_session_id",
    "proposed_action",
    "payload",
    "cryptographic_signature"
  ],
  "additionalProperties": false
}
```

### Protocol Flow

1. **Generation:** Agent $A$ generates $Intent\_Proposal_{A}$ based on its context.
2. **Canonicalization:** The host application canonicalizes $Intent\_Proposal_{A}$ excluding the `cryptographic_signature` field.
3. **Validation:** The host application strictly validates $Intent\_Proposal_{A}$ against the `SwarmConsensusIntent` JSON Schema. If validation fails, the intent is immediately rejected.
4. **Verification:** The cryptographic signature is verified against Agent $A$'s public key.
5. **Consensus:** The validated intent is placed on the deterministic shared ledger. The deterministic execution engine evaluates all proposals for `swarm_session_id` and computes the state transition only if consensus rules are met.

## Rationale

The restriction of multi-agent communication strictly through standardized intent ledgers rather than agent-to-agent prompt sharing isolates the risk of chained hallucination and prompt injection spreading across a swarm. By enforcing a strict JSON Schema and explicitly rejecting additional properties, the host system is shielded from unpredictable behavior generated by the probabilistic LLMs. Cryptographic signatures ensure the integrity of the data source within the deterministic boundaries.

## Backwards Compatibility

This ERC is fully backward-compatible with SDIC-1 v1.0.0-draft implementations. It extends the existing Action Ledger concept without modifying the core Pilier 1 to 4 mechanics.
