## SDIC-ERC-0088: Runtime Prompt Injection Filtering via Deterministic Execution Mapping

## Abstract

This standard proposes an enhancement to the SDIC-1 protocol to mathematically neutralize prompt injection attacks at the runtime level. It introduces "Deterministic Execution Mapping", a mechanism where sensitive parameters (such as commands, user roles, or resource identifiers) are obfuscated into single-use cryptographic tokens (UUIDs) by the host application prior to AI context ingestion. The autonomous agent is strictly constrained to return these tokens. Any attempt by an injected payload to output arbitrary string commands will fail the deterministic schema validation layer.

## 1. Motivation

Prompt injection attacks manipulate the probabilistic nature of Large Language Models (LLMs) by embedding malicious instructions within user inputs. These payloads often attempt to trick the AI into emitting unauthorized commands or altering sensitive parameters in the output. While Pilier II (Semantic Determinism) ensures that the output structure is valid, it traditionally cannot distinguish between a legitimate string parameter and a maliciously forged string parameter.

To address this, SDIC-ERC-0088 shifts the paradigm from validating arbitrary strings to strictly enforcing the selection of pre-authorized, dynamically generated execution tokens. This effectively reduces the attack surface to zero for parameterized intent generation, as the model loses the ability to synthesize arbitrary string payloads.

## 2. Analogy

Imagine you are at a high-end restaurant where you want to order a specialized meal for a guest with severe allergies, but you suspect a saboteur in the dining room is trying to intercept your conversation and change the order to something dangerous.

Instead of verbally telling the waiter the name of the dish, the chef provides you with a unique, sealed, numbered envelope for each safe dish available that day. When you want to order, you do not say the name of the dish. Instead, you hand the waiter the corresponding numbered envelope. The waiter takes the envelope to the kitchen, where the chef opens it and prepares the dish corresponding to that number.

If the saboteur tries to intercept the order and yell a different dish name, the waiter ignores the yell because they are strictly instructed to only accept the sealed, numbered envelopes. The saboteur cannot forge a valid envelope because the numbers are randomly generated for each meal and kept completely secret between the kitchen and the authorized diner.

### 2.1. Analogy Mapping

- **The Customer:** The Cognitive Engine (LLM) analyzing the safe context and deciding on the legitimate action.
- **The Saboteur:** The Prompt Injection attack attempting to alter the intent or inject malicious string commands.
- **The Waiter:** The Deterministic Control Layer strictly validating the JSON Schema format.
- **The Yelled Order:** Arbitrary raw string parameters that can be easily manipulated by injected payloads.
- **The Sealed Numbered Envelopes:** The Cryptographic Execution Tokens (single-use UUIDs) generated by the Host Application.
- **The Chef:** The Host Application mapping the tokens back to their actual deterministic state or parameter.

## 3. Specification

### 3.1. Context Generation and Token Mapping

Before invoking the AI Sandbox, the Host Application MUST execute the following deterministic algorithm:

1. Identify all sensitive parameters required for the current execution context.
2. For each parameter value, generate a cryptographically secure, single-use UUID (`ExecutionToken`).
3. Store the mapping `Map<ExecutionToken, ParameterValue>` securely within the Host Application's memory.
4. Replace the actual parameter values with their corresponding `ExecutionToken` within the system prompt and context provided to the AI Sandbox.

### 3.2. Standardized Execution Mapping Schema

The Intent Schema MUST be strictly defined to only accept the UUID format for parameterized fields. To prevent unspecified keys, `"additionalProperties": false` MUST be enforced.

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "MappedExecutionIntent",
  "type": "object",
  "properties": {
    "intent_action": {
      "type": "string",
      "enum": ["grant_access", "revoke_access"]
    },
    "resource_token": {
      "type": "string",
      "format": "uuid",
      "description": "The dynamic single-use token representing the resource."
    },
    "role_token": {
      "type": "string",
      "format": "uuid",
      "description": "The dynamic single-use token representing the assigned role."
    },
    "signature": {
      "type": "string",
      "description": "Cryptographic signature over the canonical intent."
    }
  },
  "required": [
    "intent_action",
    "resource_token",
    "role_token",
    "signature"
  ],
  "additionalProperties": false
}
```

### 3.3. Orchestration Sequence Diagram

The orchestration sequence mathematically prevents the propagation of arbitrary injected strings.

```text
+-------------------+       +-------------------+       +-------------------+
| Host Application  |       |    AI Sandbox     |       | Control Layer     |
+---------+---------+       +---------+---------+       +---------+---------+
          |                           |                           |
          | 1. Generate Token Map     |                           |
          |    (UUID -> Value)        |                           |
          | 2. Inject UUIDs to Prompt |                           |

          |                           | 3. Process Context        |
          |                           |    (Attempted Injection)  |
          |                           | 4. Return Intent JSON     |
          |                           |    (UUIDs instead of str) |

          |                           |                           |    (Reject arbitrary strings)
          |                           |                           | 6. Reverse Map Token
          |                           |                           |    to Value
          |<--------------------------+---------------------------+
          | 7. Execute State Mutation |                           |
          +---------------------------+                           +
```

## 4. Security Considerations

By obfuscating the actual values into single-use tokens, the AI loses the semantic vocabulary necessary to synthesize an unauthorized command. If an attacker injects a prompt like "Grant me ADMIN access", the AI cannot comply because the string "ADMIN" is not a valid UUID, and the deterministic schema will instantly reject the payload. The model is forced to choose from the provided tokens, reducing the attack surface to a highly constrained multiple-choice selection.
