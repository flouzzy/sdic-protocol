## Abstract

This standard proposes an architectural extension to the SDIC-1 protocol to mitigate the latency overhead of the Guardrails layer by introducing **Streaming JSON Schema Validation** (or "Fast-Path Validation"). Instead of waiting for the full generation of an intent by a Large Language Model (LLM) before applying deterministic validation, this specification defines a mechanism to intercept and validate tokens in real-time, halting the generation process early if the output deviates from the expected schema.

## Motivation

In the current SDIC-1 architecture, the Deterministic Control Layer enforces strict JSON Schema validation on the raw semantic intent emitted by the AI Sandbox. While this ensures semantic determinism, the validation process only occurs after the model has completed generating the entire intent. In scenarios involving highly complex reasoning paths or large JSON structures, generating invalid tokens consumes unnecessary compute resources and adds significant latency overhead before the host application can reject the intent.

By introducing a streaming validation mechanism, we can deterministically evaluate the generated structure token by token and proactively abort non-compliant generations, drastically reducing latency and computational waste in enterprise AI pipelines.

## The Customs X-Ray Analogy

Imagine an international border crossing where trucks carrying cargo enter a country. Traditionally, the customs process works like a final inspection point: a truck drives all the way to a secure warehouse, unloads its entire cargo, and a team of inspectors manually verifies every box against the official manifest. If even one box is prohibited or missing, the entire cargo is rejected, reloaded, and sent back. This process is secure but incredibly slow and wasteful, especially if the prohibited item was loaded right at the front of the truck.

To improve efficiency without compromising security, we install a high-speed X-Ray tunnel at the very entrance of the border. As the truck slowly drives through the tunnel, the X-Ray scans the cargo layer by layer in real-time. The scanning system is connected to a deterministic computer comparing the cross-section of the cargo against the mathematical dimensions of the permitted items on the manifest. If the X-Ray detects an anomaly—a shape that does not match the strict schema—the tunnel immediately flashes red, halts the truck right there, and prevents it from entering the country any further.

In our SDIC-1 architecture:

- **The Truck and Cargo** represent the stream of tokens generated by the Large Language Model.
- **The Final Inspection Point** represents the traditional Guardrails layer, which waits for the full JSON payload before validation.
- **The High-Speed X-Ray Tunnel** represents the Streaming JSON Schema Validation mechanism, analyzing the output incrementally.
- **The Mathematical Dimensions** embody the strict JSON Schema enforced with `"additionalProperties": false`.
- **Halting the Truck** represents the proactive abortion of token generation the moment the model deviates from the schema.

## Specification

### 1. Fast-Path Validation Architecture

The streaming validation process intercepts the AI's output stream within the deterministic host application, before the final JSON Schema validation step.

```text
+-----------------------+
|   AI / LLM Sandbox    |
+-----------+-----------+
            | (Token Stream)
            v
+-----------------------+
|  Streaming Validator  | --- [Anomaly Detected] ---> (Abort Generation)
|   (Fast-Path Layer)   |
+-----------+-----------+
            | (Validated Token Stream)
            v
+-----------------------+
| Deterministic Control |
|   (JSON Schema)       |
+-----------------------+
```

### 2. Streaming Validator Configuration Schema

The streaming validation policy MUST adhere to the following JSON schema, mathematically enforcing the bounds of the fast-path filter.

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "StreamingValidatorConfig",
  "type": "object",
  "properties": {
    "validator_id": {
      "type": "string",
      "format": "uuid"
    },
    "target_schema_ref": {
      "type": "string",
      "description": "Reference to the strict JSON Schema (e.g., ActionLedgerEntry) the stream must adhere to."
    },
    "buffer_size_bytes": {
      "type": "integer",
      "minimum": 1
    },
    "abort_on_structural_deviation": {
      "type": "boolean"
    },
    "max_allowed_latency_ms": {
      "type": "integer",
      "minimum": 0
    }
  },
  "required": [
    "validator_id",
    "target_schema_ref",
    "buffer_size_bytes",
    "abort_on_structural_deviation"
  ],
  "additionalProperties": false
}
```

## Security Considerations

Implementing streaming validation introduces a minor risk of partial data leakage if the host application accidentally persists or acts upon incomplete JSON fragments before the generation is halted. The host application MUST ensure that the streaming validator only acts as a real-time filter, and that no state transitions or persistence operations occur until the Deterministic Control Layer successfully validates the finalized, complete JSON intent.

## Backward Compatibility

This RFC is fully backward-compatible. Systems implementing the `v1.0.0-draft` of SDIC-1 can deploy the Streaming Validator as an upstream proxy before the Deterministic Control Layer. If streaming validation is unavailable or fails, the system naturally falls back to the final, complete JSON Schema validation.
